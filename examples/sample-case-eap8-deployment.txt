Product: JBoss EAP
Version: 8.0.1
JDK: OpenJDK 21.0.1
OS: RHEL 9.3
Deployment: Standalone (single node, development environment)

Issue Description:
Application that was previously deployed on EAP 7.4 fails to deploy on EAP 8.0
with ClassNotFoundException for javax.servlet.http.HttpServlet. The customer has
migrated their application from Java EE to Jakarta EE, updating all their own
source code to use jakarta.* packages. However, some third-party libraries bundled
in the WAR still reference javax.* classes internally.

The customer's application (app.war) includes the following third-party JARs in
WEB-INF/lib:
  - legacy-utils-1.2.jar (internal company library, source not available)
  - old-reporting-3.5.1.jar (open source, but latest version still uses javax.*)
  - custom-auth-filter-2.0.jar (vendor library, javax.servlet.Filter impl)

The customer has already:
  1. Migrated all their own code from javax.* to jakarta.*
  2. Updated pom.xml to use Jakarta EE 10 dependencies
  3. Updated web.xml to Jakarta EE 10 schema
  4. Updated persistence.xml to Jakarta Persistence 3.1 schema
