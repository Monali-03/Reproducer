Product: Red Hat Data Grid
Version: 8.4.6
JDK: OpenJDK 17.0.9
OS: RHEL 9.3
Deployment: OpenShift 4.14

Issue Description:
Cross-site replication between two Data Grid clusters (NYC and LON) is failing
intermittently. The LON site stops receiving updates from NYC after approximately
2 hours of operation. No errors visible on NYC side. LON site shows stale data.

The clusters are connected via RELAY2 with bridge nodes. Each site has 3 Data Grid
pods in a StatefulSet. The Data Grid Operator (version 8.4.5) is managing both
clusters.

The issue first appeared after scaling the NYC cluster from 2 to 3 pods. Prior to
scaling, cross-site replication was stable for weeks.

Reproduction Steps:
1. Deploy Data Grid to both OpenShift clusters using the Operator
2. Create the "customer-data" cache with cross-site backup
3. Write data to NYC site using Hot Rod client
4. Verify data appears on LON site (works initially)
5. Wait approximately 2 hours
6. Write new data to NYC site
7. Check LON site -- data is stale, new entries are missing
8. Restart datagrid-0 pod on LON site
9. Replication resumes and missing data appears (state transfer works)

Expected Behavior:
Data written to NYC should be replicated to LON within seconds, continuously.

Actual Behavior:
Replication works initially but stops after approximately 2 hours. LON shows stale
data. Manual restart of LON bridge node (datagrid-0, which is the site master)
temporarily restores replication. The issue recurs after another ~2 hours.

Suspected Root Cause (customer):
Customer suspects the AWS NLB idle timeout (350 seconds) may be closing the TCP
connection used by RELAY2, but JGroups does not detect the broken connection and
continues to believe the bridge is active. They have tried adjusting the NLB idle
timeout to 3600 seconds but the issue persists (just takes longer to manifest).

Additional Information:
- Data Grid heap usage: ~60% of 2Gi limit
- Pod resource limits: 2 CPU, 2Gi memory
- No OOMKilled events
- No pod restarts during the failure window
- OpenShift node health checks pass
- Cross-site latency (us-east-1 to eu-west-2): ~80ms average
