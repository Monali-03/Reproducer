Product: JBoss EAP
Version: 8.1.0
JDK: OpenJDK 17
Deployment: Standalone HA (2 nodes behind Apache mod_cluster)

Issue Description:
Customer reports intermittent session loss when one EAP node is restarted during
load testing. Users are being redirected to the login page after a node restart,
even though sessions should be replicated across the cluster.

The application uses HTTP sessions to store user authentication state and shopping
cart data. The environment uses mod_cluster for load balancing with sticky sessions
enabled.

The customer has confirmed that both nodes are members of the same cluster and
that the Infinispan distributed cache is configured with 2 owners. They also
confirmed that JGroups is using a TCP stack with MPING discovery on a multicast-
capable network.

Reproduction Steps (from customer):
1. Deploy application to both nodes
2. Start both EAP nodes and verify cluster formation
3. Login to application via mod_cluster VIP
4. Add several items to shopping cart
5. Confirm session is visible on both nodes via JMX
6. Restart the node that owns the session (check via JSESSIONID route suffix)
7. Next request after failover fails with "Session is invalid" error

Expected Behavior:
Session should fail over to the surviving node seamlessly. The user should continue
their shopping session without being redirected to the login page.

Actual Behavior:
Session is lost and user must re-login. Shopping cart data is lost. The issue occurs
approximately 70% of the time during restarts. When it does not occur, the failover
works correctly.

Additional Notes:
- Issue does not occur with REPL_SYNC cache mode (but performance is unacceptable)
- Customer suspects it may be related to Infinispan state transfer timing
- TCP connection timeout between nodes is set to default (20 seconds)

JVM Options:
